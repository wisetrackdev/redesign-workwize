POINT 1 [DONE] Owner Comment History Tracker

Requirement: Maintain a history of all comments added by the job owner rather than overwriting past entries.

Backend Implementation:

Fixed legacy bug where DELETE FROM op_job_tracker_comments WHERE commentId="OWNERCOMMENT" wiped past history. Each new owner comment now generates a unique ID OWNERCOMMENT_{ticks} and is chronologically queried by GetJobWiseComments.

Frontend Implementation:

In job-details.html & job-details.js, built an expandable history container displaying total count badge, latest comment at top, and full historical log of previous comments with timestamps.

POINT 2 [DONE] Inactive Team Management (Admin Page)

Requirement: Add an option to view and manage inactive teams on the Admin Page.

Database & Backend:

Added column isactive TINYINT(1) NOT NULL DEFAULT 1 to op_property_teams. Created database method ToggleTeamStatus and endpoint [HttpPost("toggleteamstatus")] in AdminController.cs.

Admin Frontend:

Added STATUS column, filter button group ("All Teams", "Active Teams", "Inactive Teams"), status badges, and action buttons to activate/deactivate teams with instant table refresh.

POINT 3 [DONE] Job Details on Hover

Requirement: Display job details when the user hovers over the Job Details column.

Frontend Implementation:

In both all-jobs.js and jobs.js (Area Modal), added a floating hover preview card to the DETAILS table cell. Shows full untruncated job description, area, and location on mouseover smoothly without clipping.

POINT 4 [DONE] Job Details in Exported File

Requirement: Include the Job Details column in exported files.

Frontend Implementation:

In exportJobsToCSV (All Jobs) and exportAreaJobsToCSV (Area Modal), included the DETAILS column with multiline cleaning and RFC 4180 CSV escaping.

POINT 5 [DONE] Display All Areas (Even with 0 Tasks)

Requirement: Show all areas on the main page, even if no tasks are currently assigned to them.

Backend & Frontend Fix:

Modified backend JobOverView to query all operational areas and append missing areas with 0 counts. Also added client-side union merge with ALL_OPERATIONAL_AREAS.

POINT 6 [DONE] Support All File Attachments

Requirement: Allow users to upload all file types while creating a job, not just images.

Implementation:

Updated all modal file inputs across 8 HTML files to accept="*/*". Removed extension restriction in main.js, raised file limit to 25MB, and added rich file icons (PDF, Word, Excel, ZIP, Images).

POINT 7 [DONE] Job Status Permissions

Requirement: Allow only the assigned team (or Admins) to change the status of a job.

Backend & Frontend:

In Opro_Business_Layer.cs, added strict team membership validation throwing UnauthorizedAccessException on status update attempts by unassigned non-admins. Added client permission checks in job-details.js and all-jobs.js.

POINT 8 [DONE] View-Only Access Across Resorts (Atmosphere Admin)

Requirement: Provide view-only access to specific areas across all resorts for Atmosphere Admin.

Implementation:

Implemented applyAtmosphereAdminViewOnlyMode() in job-details.js which detects Atmosphere Admin credentials, hides all modification/edit controls, and displays an amber view-only status indicator badge.

POINT 9 [DONE] Additional Email Notifications

Requirement: Review and define whether email notifications are required for events other than job assignments.

Audit & Implementation:

Defined and implemented 4 core lifecycle triggers: Job Status Change, Job Closure, Owner Comment Added (SendEmailForOwnerComment), and Critical Safety Alerts (SendEmailForSafetyAlert) in EmailService.cs.

POINT 10 [DONE] Optional Villa Number (Guest Villa Jobs)

Requirement: Make the villa number optional for guest villa jobs.

Implementation:

In main.js, removed the blocking validation on villa number for Guest Villa areas, set placeholder to e.g. V-101 (Optional), and hid the red asterisk.
